# CLAUDE.md

## What this is

`MIS Signals` (`com.mochoindiestudio.signals`) is a **standalone UPM package** — not a Unity project.
`package.json` is at the repo root; the code is under `Runtime/`. It is the shared primitive behind
three sibling packages: **MIS Dialog System**, **MIS Quest System**, **MIS Inventory System**. They
integrate through a game by publishing/subscribing on this one channel instead of referencing each
other's assemblies.

Built **Minimal** (v0.1.0, 2026-09-02):
- `MisSignals` — static, stateless: `Report(string eventId, string payload = null, int amount = 1)`,
  `Subscribe`/`Unsubscribe(ISignalListener)`, `Clear()`, `ListenerCount`. Snapshots its listener list
  per dispatch so a listener may (un)subscribe during `Report`.
- `ISignalListener` — `OnSignal(string eventId, string payload, int amount)`.
- Asmdef `MochoIndieStudio.Signals`, **`noEngineReferences: true`** — no `UnityEngine`, no editor code.

## Deliberately out of scope (for now)

No `EventId` / `Payload` value types, no shared authoring widget (`SignalTrigger`) or property
drawer, no bus-per-domain wrappers. A "more general" version is planned **only after** Dialog +
Quest + Inventory are all stable against this Minimal API — the user asked to be advised when that
point is reached. Don't add surface area speculatively.

## Working on this package

There is no Unity Editor in this folder. To compile/test a change you go through a **consumer
project** that references this package `file:` — currently **MIS Inventory System** at
`E:\Mocho Indie Studio\MIS Inventory System` (`"com.mochoindiestudio.signals": "file:../../MIS Signals"`
in its `Packages/manifest.json`; the two folders must stay siblings under `E:\Mocho Indie Studio\`).

- Edit files here, then in the consumer project: `unity command recompile --port <consumer>` and
  poll `recompile_status` / `console --level error`. New `.cs` files may need the user to do
  **Assets ▸ Reimport All** in the consumer (embedded/`file:` package file-watcher quirk).
- `.meta` files ARE committed here (UPM needs them) and are generated by the consumer's Editor on
  import — don't hand-write them; let Unity create them, then commit.
- Unity CLI notes: see the MIS Inventory System repo's `docs/unity-cli.md`. PATH for the Bash tool:
  `export PATH="$PATH:/c/Users/crist/AppData/Local/Unity/bin"`.

## Conventions

- Namespace `MochoIndieStudio.Signals`. Studio C#/Unity guidelines: composition over inheritance,
  deterministic, no LINQ/GC in hot paths (`Report` is a hot path — keep it allocation-light beyond
  the per-dispatch snapshot), documented code, no magic numbers.
- Keep the assembly `UnityEngine`-free. Anything needing `[SerializeField]` / attributes belongs in
  a *consumer* or a future `.Authoring` split, not here.
- Version in `package.json`; Keep a Changelog in `CHANGELOG.md` at root. Never bump major without an
  explicit request. Work on `development`, PR `main` only when asked.
- Remote: planned `mochoindiestudio/MIS-Signals` (not yet created/pushed as of 2026-09-02).
